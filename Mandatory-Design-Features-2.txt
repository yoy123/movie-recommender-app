## New reported issues and required changes — 2026-10-12

9. Fix OpenAI-powered recommendations. On the Firestick, the recommendation request reports "unauthorized" and falls back to TMDB. Determine whether this is a missing/incorrect configured API key, a key or project permission/billing problem, an inaccessible or unsupported model, or another API response. Log useful sanitized failure categories/status codes for debugging without displaying or exposing secret keys. Restore reliable AI-first recommendations using an API-accessible supported model and compatible requests, retaining TMDB fallback with a clearly identified reason when AI actually fails. Verify with a real request and an on-device test; do not treat compilation as proof of authorization.

10. In Favorites, add "Select for Recommendations" to each movie/show's card options alongside "Watch Options" and "Delete from Favorites". Support both adding and removing a selection, show its selected state, respect the maximum of five recommendation inputs and movie/TV mode, and ensure Firestick DPAD/OK can reach and activate the action. Selecting an existing favorite as an input does not mean it may be returned as a recommendation; saved favorites must still be excluded from recommendation results.

11. Redesign Favorites to visually match the Firestick front/home browse menu: use separate labeled Movies and TV Shows rows with horizontally scrolling left-to-right poster cards, NOT a vertical grid. Match home card artwork, sizes, spacing, typography and focus. DPAD Left/Right moves between cards; Up/Down changes rows; OK opens Watch Options, Select for Recommendations / Remove from Selections, and Delete from Favorites; Back returns to the same card with focus/scroll retained. Keep search, selected-state indicators and the five-item limit. The mobile UI should use comparable swipeable horizontal Compose rails. This is an outstanding design and functionality requirement, not a completed fix.

12. Diagnose and fix TMDB fallback producing exactly the same recommendation list for completely different sets of selected titles. Verify that the correct selected IDs/titles and content mode reach candidate discovery and scoring on every request; check for stale ViewModel state, cache reuse, broad/global candidate pools, hard-coded ranking, and missing similarity weighting. Results should reflect the actual selections, preferences, and exclusions without pointless randomness. Add controlled A-vs-B input tests and on-device regression checks so materially different selections do not produce an identical full list unless legitimately unavoidable; keep session deduplication and favorites exclusions working.

These four points are reported requirements/bugs, not confirmed fixes. Do not mark them completed until validated in the affected Firestick UI and relevant automated/live API tests.
